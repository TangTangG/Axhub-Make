01 / Overview

Touch And Talk 批注演示规格

本规格从当前 index.tsx、style.css、四张本地截图和公共 Hash 路由实现反向归纳，描述一个六章教程式演示。它记录页面实际渲染的教学内容与章节交互，不把教程中的语音、提示词或技能操作扩写为当前组件已经执行的能力。

文档状态当前实现事实
原型入口批注演示 / touch-and-talk-annotation-demo
默认章节cover / Touch And Talk

基线与定位

当前原型是带章节目录的教学演示或演示文稿。它用文案、图标和截图介绍 Touch And Talk 式批注协作，实际运行层只负责选择一个章节、渲染对应内容并通过 Hash 切换章节。

  • 页面注册六个章节，顺序固定为 cover、quick-flow、voice-annotation、common-tips、quick-execute、more-scenarios。
  • 每次只渲染一个 ChapterContent 分支；左侧导航和页脚前后页按钮共用同一章节数组。
  • 四张 PNG 作为教程截图呈现，组件没有为图片内部控件绑定事件。
  • 页面未导入麦克风、语音识别、剪贴板、提示词执行、技能执行或标注运行时 API。

事实来源与优先级

  1. client/src/prototypes/touch-and-talk-annotation-demo/index.tsx：章节、标题、摘要、教学文案、图片映射、导航和可访问性属性。
  2. client/src/prototypes/touch-and-talk-annotation-demo/style.css：布局、色彩、深浅章节、焦点、断点和图片呈现方式。
  3. client/src/prototypes/touch-and-talk-annotation-demo/assets/*.png：四张当前导入的截图及其像素尺寸。
  4. client/src/common/useHashPage.ts：Hash/查询参数解析、Hash 写入和嵌入宿主路由通知。
  5. 仓库 HTML 规格模板、已批准的默认原型主规格设计和当前仓库规则：本规格自身的文档结构与交互约束。

当教程文案与可执行代码的能力范围不同，规格分别记录“页面声称或指导什么”和“当前组件实际调用什么”，并以可执行源码作为能力判断依据。

受众与目的

主要受众

需要理解 Make 页面批注协作方式的原型评审者、设计参与者和实现参与者。页面没有登录、角色选择或权限分支。

核心目的

按六章顺序说明点选元素、输入或口述意图、常用编辑技巧、快速执行教学路线和扩展批注场景。

主要阅读任务

从封面建立概念，查看四步快速批注，阅读语音建议与四个技巧，再理解两条执行教学路线和三个场景。

完成判断

当前页面没有进度保存、完成按钮或测验；读者到达末章只表示线性导航的末端。

范围

  • 六个章节的页面键、顺序、目录标签、标题、眉题、摘要和 tone。
  • 封面三条原则、快速批注四步、语音示例与建议、四个常用技巧、两条执行路线和三个扩展场景。
  • 四张截图的导入文件、标题、替代文本、说明和当前组件位置。
  • 章节 Hash、当前态、前后页禁用边界、未知页面回退、嵌入宿主路由消息。
  • 当前局部样式的结构、响应式断点、键盘焦点和语义属性。

非目标

  • 不把“语音输入效率是普通的4倍，提升 40% 的沟通效率”验证为测量结论；这是当前章节摘要原文。
  • 不实现或声称页面会请求麦克风权限、录音、转写、纠错或选择豆包系语音模型。
  • 不实现或声称截图中的发送按钮、提示词直接执行、AI 修改或技能读取会由本组件触发。
  • 不实现双击编辑、样式编辑、图片粘贴、选择元素开关、移动端批注或双端批注；这些是教程陈述的其他产品操作或场景。
  • 不添加 Make 批注回写、评审运行时集成、用户数据、后端请求、进度状态或分析埋点。

Hash 路由

  • defineHashPageRoute 注册六个页面，默认页为 cover。
  • 标准地址形式为 #page=cover、#page=quick-flow、#page=voice-annotation、#page=common-tips、#page=quick-execute 和 #page=more-scenarios。
  • 初始化优先读取 Hash 中的 page，再读取查询参数 ?page=，最后回退默认页。
  • 页面 ID 的语法只允许小写字母、数字和连字符；setPage 将合法值写为 window.location.hash = "page=" + pageId。
  • 公共 hook 不校验语法合法的页面键是否属于当前 route。若 Hash 是未注册但格式合法的值，组件以索引 0 渲染封面，但不会自行改写该 Hash。

03 / Chapter Specifications

章节规格

本页逐章记录当前可见内容、结构与素材。引号中的效率、产品操作和 AI 行为均是教程正文的一部分；是否由当前组件执行，统一按交互边界单独判断。

01 · cover / Touch And Talk

摘要：老罗在早年就预见到了与 AI 最好的协作方式之一。TNT 就是最自然、最快速、最准确的与 AI 沟通方法。

封面宣言

点中元素 → 说出想法 → 交给 AI。三段文字用两条装饰线连接。

视觉结构

上部为封面文案与紧凑截图双列，下部为三条原则；章节使用 hero-dark tone。

编号原则说明
01位置不用解释批注天然绑定元素，AI 不需要猜“左上角那个卡片”到底是哪一个。
02意图不离现场修改原因、视觉偏好、例外条件，都和页面一起进入上下文。
03交付不是截图最终交给 AI 的，是可执行的页面和批注，而不是聊天记录里的零散描述。

截图：annotation-cover.png；标题“批注演示”；替代文本“移动端页面中开启批注后的产品截图”；说明“批注后快速微调页面。”

02 · quick-flow / 快速即可体验

摘要：从打开批注到复制提示词，目标是让一次局部修改在 30 秒内完成表达。

顺序步骤当前教程说明
01开启批注打开原型顶部的批注入口，让页面进入可点选状态。
02选择元素选中按钮、卡片、图表或文字，任意元素都可以批注。
03输入批注写一句要改什么；能说清目的，比格式漂亮更重要。
04复制提示词把页面批注整理成 AI 能执行的上下文。

截图：quick-annotation-flow.png；标题“快速批注”；替代文本“快速批注流程截图”；说明“选中页面内容后，用批注说明需求和判断依据。”

“30 秒”“任意元素都可以批注”和“复制提示词”是教程当前文案。该章节组件只渲染四张步骤卡与一张截图，没有计时器、元素选择、批注输入或复制处理函数。

03 · voice-annotation / Talk 是另一重点

摘要：语音输入效率是普通的4倍，提升 40% 的沟通效率。

像录口播一样说

语音批注的价值不在“更正式”，而在更快。不用担心语气，语病和错误，AI 很聪明都能理解。

转写示例

“嗯，这个元素我想改成折线图。” → “那个，还是不要吧，改成面积图。” → 强调“AI 以最后意图为准：改成面积图。”

可能有利于身心健康

AI 也会犯错。把情绪和修改意见直接说出来，是一个无害的发泄出口。

优先豆包系

语音输入工具优先选择豆包或支持豆包大模型，例如闪电说，中文识别更稳。

本章呈现的是静态文字、AudioLines/Bot/CheckCircle 图标和示例转写。当前组件不请求麦克风权限、不采集音频、不调用语音识别，也不验证“4倍”“40%”或模型识别效果。

移动端批注

05 / Evidence & Acceptance

证据与验收

验收项只覆盖当前源码能够证明的教程内容、章节交互和文档自身行为。勾选状态保存在当前浏览器的独立命名空间，不发送给 Make，也不改变原型。

已知边界

  • 原型是六章教程或演示文稿，不是批注输入器、语音工具、助手面板或技能运行器。
  • “4倍”“40%”“30 秒”“中文识别更稳”等为当前教程文案，源码中没有实验数据、测量逻辑或来源引用。
  • 截图展示其他界面状态，但当前页面没有让读者操作截图内控件，也没有热点映射。
  • 双击文本、编辑样式、粘贴图片、恢复交互、文档批注、移动端批注和双端批注都是说明内容，不是本组件注册的交互。
  • 页面上直接执行和技能读取批注均为说明路线；当前组件不提交提示词、不修改页面、不读取批注、不调用技能。
  • 公共 Hash hook 在嵌入父窗口时只通知路由信息和页面变化；没有 Make comment writeback 或 review runtime 标记。
  • 页面没有后端请求、身份权限、错误状态、加载状态、完成进度、用户偏好或持久化数据。
