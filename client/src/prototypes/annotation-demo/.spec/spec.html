01 / Overview

标注演示规格

本规格从当前可运行原型、标注源、目录文档、局部样式和公共 Hash 路由实现反向归纳，描述当前已经存在的七章标注协作演示。规格不读取或改写原型状态，也不向 Make 批注宿主回写内容。

文档状态当前实现事实
原型入口标注演示 / annotation-demo
默认章节prototype-as-prd

目的与成功口径

原型用于说明 Axhub Make 的标注能力如何把可运行原型、节点说明、状态控制和补充文档放在同一个评审入口里。其表达关系是：原型承载界面和交互，标注补充边界、原因和决策，目录组织页面、文档和外部来源。

当前演示的成功口径是让评审者能够沿七章页面理解“原型即 PRD”、内容标注、状态标注、原型目录、开启标注、编辑标注和 Agent 读取；目录入口还应能切换页面、阅读六篇 PRD 文档并打开一个外部设计来源。

事实来源与优先级

  1. 当前可运行实现：index.tsx、style.css 与公共 useHashPage.ts 决定实际章节、文案、状态渲染、样式和路由行为。
  2. annotation-source.json 决定标注节点、颜色、Markdown 正文、分段控件及目录树。
  3. docs/prd-00-overview.md 至 docs/prd-05-handoff.md 提供角色、流程、状态、风险和交付语义，并由入口以原始文本导入后内联到目录。
  4. 仓库原型规则与已批准的“三原型 HTML 主规格设计”约束主规格形式；当文档描述与页面表现不一致时，原型内流程文档明确以可运行原型为主。

使用者与职责

产品负责人

确定页面目标、业务边界、验收标准，并判断标注内容是否表达清楚。

设计师

确认页面结构、视觉规则、交互状态和设计来源是否统一。

研发

根据可运行原型和节点标注理解页面行为、状态条件和实现优先级。

评审者

从目录进入相关页面或文档，并通过标注理解问题、风险和决策。

Agent

基于页面结构、需求资料和既有规则生成第一版标注、目录和补充文档，再由人工校正。

目录中的页面和文档默认用于评审阅读；标注编辑、状态配置和生成结果确认由项目维护者完成。

当前范围

  • 七个 Hash 章节及侧栏、上一页、下一页导航。
  • 任意元素说明、Markdown 正文、三种功能性标注颜色、颜色筛选和同一节点多条标注的演示。
  • 结果、列表、指标三类状态及其由标注分段控件提供的分支。
  • 由页面、六篇 PRD 文档和一个外部链接构成的原型目录。
  • 开启标注的三种方式、编辑标注的两组方式，以及 Agent 读取四类上下文的说明。

当前非目标

  • 不覆盖真实后端接口、用户权限系统、多人实时协作冲突处理或正式发布审批流。
  • 结果卡按钮仅呈现“查看详情”或“重新提交”文案，没有点击处理函数，不构成真实提交与恢复流程。
  • 状态值来自 useProtoDevState 与标注控件，不接入真实业务数据。
  • 本规格的搜索、Hash 和验收勾选只服务文档自身，不与原型、AnnotationViewer 或 Make 宿主同步。

路由行为

  • defineHashPageRoute 注册七个页面，默认页为 prototype-as-prd；标准地址形式为 #page=<pageId>。
  • 页面 ID 只接受小写字母、数字和连字符。初始化时先解析 Hash，再解析查询参数 ?page=，最后回退默认页。
  • setPage 写入 window.location.hash = "page=" + pageId；侧栏、页脚和目录 route 都调用这一入口。
  • Hash 变化后 hook 更新页面状态并通知宿主。无 #page= 时，Hash 变化会再次尝试查询参数，然后回退默认页。
  • hook 只校验 ID 格式，不校验 ID 是否在七页清单内；入口组件找不到章节时以索引 0 显示“原型即 PRD”。

03 / Flows & States

流程与状态

主流程来自原型内流程文档；页面中的交互则由 Hash hook、AnnotationViewer 配置与三组分段控件共同完成。

主要协作流程

  1. 生成或维护可运行原型，使页面结构、交互路径和关键状态可直接查看。
  2. 为关键节点补充内容标注，说明字段含义、业务规则、例外和设计判断。
  3. 为需要评审的业务状态增加状态标注，包括成功、失败、空列表和指标异常。
  4. 把页面、PRD 文档和设计来源整理进同一个原型目录。
  5. 开启标注后，通过 AI 或手动方式编辑标注。
  6. 开发 Agent 通过技能读取源码、标注、文档和截图，用于后续开发。

可观察的设计基底

原型侧栏明确显示“STYLE B · SWISS INTERNATIONAL”和“IKB · #002FA7”。源码没有引用原型专属 DESIGN.md；因此本规格只记录页面和样式中可见的 Swiss 文档式表达，不推断额外主题规则。

  • 基础色：纸张 #fafaf8、墨色 #0a0a0a、强调色 IKB #002FA7；标注色为 #D97706、#059669、#7C3AED，危险色为 #E11D48。
  • 桌面布局为 270px 侧栏加弹性正文；正文最大内宽 980px。侧栏使用 sticky，章节标题、细边框、等宽元信息和克制的灰阶形成文档阅读层级。

  • 目录页锁定 100vh 并隐藏页面滚动，正文与指向右侧工具栏的固定箭头并列。

05 / Evidence & Acceptance

证据与验收

验收项只检查当前实现已经承诺的内容。勾选状态保存在当前浏览器的独立命名空间，不发送给 Make，也不改变原型。

已知边界

  • 原型演示的是标注运行时与目录协作，不包含后端、身份权限、多人实时冲突或发布审批。
  • 结果卡的错误文案提到网络或权限异常，但页面没有网络调用、权限检测或重试处理。
  • 状态控件由标注运行时注入 proto state；离开该运行时上下文时，归一化函数显示三个默认分支。
  • AnnotationViewer 的工具栏、目录阅读、颜色筛选与主题切换由外部包实现；本原型只传入 source 和 options。
  • 源数据的十段 markdownMap 中，八段对应 node ID；enable-annotation-methods 与 edit-comments-methods 只有 Markdown 和页面 DOM 定位，没有列入 11 个 nodes。
  • 文档所述“Agent 读取”是演示内容；当前页面只显示四类来源和截图，不在页面内启动读取任务。
  • Markdown 文档由构建依赖图内联；目录阅读不依赖运行时请求相对 .md 文件。
