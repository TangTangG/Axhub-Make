新手指导主规格

本规格记录 Make Client 模板中 beginner-guide 的当前工作区实现：七章学习内容、Hash 章节路由、提示词复制、项目路径注入、截图用途、响应式布局和完成标准。它以当前未提交源码为事实基线，不从历史恢复旧的 Agent、模型或 AI 稳定性文案。

事实基线

规格读取的是当前工作区文件。index.tsx、style.css 与 useHashPage.ts 在取证时均有未提交修改，clipboard.ts 与本目录中的 AI 不确定性设计/实施文档尚未跟踪；这些状态是来源属性，不是本规格要修复的缺陷。

运行入口

GuideShell 是默认导出。它接收可选 config.projectPath，通过 useHashPage(guideRoute) 选择当前章节，并始终渲染同一个侧栏、章节头、完成标准和前后章页脚。

内容构成

七章均已有专用 React 内容分支，因此当前不会落入 DefaultChapterContent 的占位版式。章节结构、提示词和表格数据均直接定义在 index.tsx。

视觉构成

style.css 定义暖纸张底色、墨蓝强调色、TsangerJinKai02 衬线字体与 JetBrains Mono 数据字体；桌面为固定侧栏加正文，窄屏改为顶部目录。

浏览器能力

章节状态来自 URL Hash；复制先尝试带 copy 事件的 execCommand 回退，再尝试 Clipboard API。页面本身没有请求后端，也没有保存学习进度。

受众与目的

主要受众：首次使用 Axhub Make、尚未形成 Agent/模型选择和 AI 原型协作习惯的新手。内容允许读者从安装 Agent 开始，依次完成选模型、下指令、创建、编辑、发布和后续学习定位。

产品目的：用短章节和可执行练习建立最小闭环；重点不是讲完所有能力，而是让用户能打开正确项目、选择明确模型、与 AI 沟通、产出和修改原型，并知道交付入口。

规格目的：给实现、评审和验收提供一个可检索的当前态事实源，明确实际文案、状态、素材和边界。规格文档的五页交互独立于原型的七章 Hash。

路由契约

  1. defineHashPageRoute 注册上述七个小写连字符 ID，默认页为 install-agent；本路由不使用 group。
  2. 初始化先解析 window.location.hash 的 page 参数，再解析查询参数 ?page=，最后回到默认页。有效 ID 字符只允许小写字母、数字和连字符。
  3. setPage(pageId) 将 URL 写为 #page=<pageId>。侧栏、上一章和下一章全部调用同一入口。
  4. Hash 变化时，hook 更新章节状态；嵌入父窗口时发送 AXHUB_PROTOTYPE_PAGE_CHANGE。初始化还发送包含 pages、defaultPageId 和 activePageId 的 AXHUB_PROTOTYPE_ROUTE_INFO。
  5. 若 Hash 中的 ID 字符合法但未注册，chapters.findIndex 得到 -1 后被钳制为 0，因此界面显示第一章；源码不会主动把未知 Hash 改回默认值。

前置条件、推进与完成

前置条件

页面假定用户从 Axhub Make 项目中进入，并能使用至少一个外部 Agent。第一章负责帮助用户选择 Agent、打开当前项目和验证目录；没有账号或环境自动检测门槛。

自由跳转

七个目录按钮始终可用。没有章节锁、强制确认或完成后解锁；选择按钮立即改变 Hash。

顺序推进

上一章/下一章来自当前数组下标。第一章的上一章禁用，末章的下一章禁用；中间章节两侧均可用。

完成含义

每章底部展示三个 CheckCircle2 图标和文字。它们是阅读清单而不是表单控件，不改变状态，也不会保存到浏览器。

当前元数据差异

第三章 chapters.sections 仍为“沟通心态 / 三个技巧 / 练习任务”，正文已经在“先接受沟通成本”之后、“三个技巧”之前加入“接受 AI 的不稳定性”。本规格以实际渲染顺序为准，同时保留这项差异作为当前态事实。

01 · 安装 Agent

目标：选择一个顺手的 AI 编程工具，在 Agent 中打开当前 Make 项目，并让 AI 只检查目录。

Agent简介上手能力官网

Cursor费用高，模型齐全，软件体验好简单强cursor.com
TRAE CN 系列中文友好，国内版免费简单一般trae.ai/download
WorkBuddy中文友好，使用简单简单一般WorkBuddy 文档
  1. 先选一个 Agent：说明 IDE、CLI、在线 Agent 都可用，后续所有“让 AI 做”的步骤都发给所选工具。
  2. 在 Agent 中打开这个项目：第一张步骤卡要求从 Make 首页左上角“打开 AI”；第二张说明 WorkBuddy、TRAE Work、ChatGPT 等工具新建项目时要加入当前目录。
  3. 最后做一次确认：复制动态提示词；AI 若在正确目录，只应回复“已打开正确项目”，并且不得修改任何文件。

完成标准：已选择一个 Agent；已在 Agent 中打开本项目；AI 回复“已打开正确项目”。

03 · 给 AI 下达指令

  1. 先正常沟通：像和同事说话一样讲清楚，不要求背提示词模板；同时接受新增沟通层，新手先追求稳定。
  2. 先接受沟通成本：“单人工作”是收到需求 → 构思方案 → 自己执行；“你 + AI”增加告知 AI、确认方案、验收执行三个标为“沟通”的节点。
  3. 接受 AI 的不稳定性：这是当前工作区新增节点。引导语使用“Vibe Coding / Vibe Design”；效果卡展示同一提示词分支到结果 A/B，时间卡展示任务开始 → 反复调整（次数不定）→ 任务完成，并要求用一段时间内的平均效率提升评估协作。
  4. 三个技巧：一个任务开一个新对话；安装豆包/闪电说语音输入（文案称输入效率提升 4 倍、沟通效率增加 40%）；多提供设计参考、调整反馈和 Bug 截图。
  5. 练习一下：把“让 AI 改一张卡片”提示词发给 AI，只修改第 03 章练习卡片的标题、正文和轻量颜色。

完成标准：已用普通话描述任务；已准备截图或参考图；已复制练习提示词并发给 AI。

04 · 创建原型

  1. 直接说你要什么：创建原型不用先写方案；需求清楚时只说做什么、给谁用、看起来像什么。
  2. 三项示例：“官网首页 / 后台列表 / 活动页”；“新客户 / 门店店员 / 小商家”；“模块 / 风格 / 参考图”。
  3. 没想清楚也没关系：正文声称 Axhub Make 内置多个技能补全需求，并有“80+”设计主题补全设计。
  4. 重要提醒：优先使用编辑器的计划模式或 spec 模式，先让 AI 写计划，再确认生成；配图再次使用 plan-mode-menu.png。
  5. 练习一下：只提供“快递官网首页、面向个人寄件和小商家用户”两个方向，让 AI 补全内容和设计。

完成标准：知道清晰需求只要先说 3 项；知道想法不完整时可以让 AI 补全；已复制快递官网首页练习提示词。

起点：直接描述哪个区域、改成什么样、为什么要改；表达不清时多用“截图 + 标注”和语音。

06 · 发布原型

两个入口：右上角菜单负责云端发布和文件导出；项目菜单负责本地开发环境访问。新手只需先识别入口。

  • 右上角菜单：支持发布到云端服务，也支持导出到 Axure、Figma 和 HTML；云服务可有多种部署渠道。配图 export-menu.png。
  • 项目菜单：获取开发环境局域网地址；团队沟通或手机调试时可复制链接或扫二维码。配图 access-link-menu.png。

完成标准：知道右上角菜单可以发布和导出；知道可以导出 Axure、Figma 和 HTML；会从项目菜单获取开发环境的局域网地址。

章节导航与状态

  • 侧栏 nav 遍历 chapters 生成七个 button type="button"。当前按钮使用 is-active 类，但没有 aria-current。
  • 正文一次只渲染当前章节组件；标题、摘要、字数和时长随 activeChapter 改变。正文 section 由 aria-labelledby 关联到各自 h3 id。
  • 前后章按钮依据数组相邻项跳转，并在不存在相邻项时使用原生 disabled。导航只改变 Hash，不滚动正文到顶部。
  • 章节完成标准每次只展示当前章的三条静态文字；没有 click、checkbox、storage 或网络行为。

复制状态机

stateDiagram-v2
  [*] --> idle
  idle --> copied: 任一复制路径返回 true
  idle --> failed: 两条复制路径都失败
  copied --> idle: 1400 ms
  failed --> idle: 2200 ms
状态按钮标签进入条件离开条件
idle复制初始状态或计时结束异步复制结果返回
copied已复制copyTextToClipboard 返回 true1,400 ms 后回到 idle
failed复制失败copyTextToClipboard 返回 false2,200 ms 后回到 idle

复制实现先创建屏外只读 textarea，监听捕获阶段的 copy 事件，把 text/plain 写入 clipboardData，再调用 document.execCommand('copy')；完成后移除监听和 textarea，并恢复此前焦点。该路径失败后，才调用 navigator.clipboard.writeText。两个入口都不可用或抛错时返回 false。

每个提示词组件各自维护状态；复制按钮自身带 aria-live="polite"，因此标签变化承担成功/失败播报。重复快速点击会创建多个回到 idle 的计时器，当前实现没有取消旧计时器。

项目路径注入

  1. getProjectPath 将可选 config.projectPath 转为字符串并去除首尾空白；缺失、null 或空白结果都是空字符串。
  2. createVerificationPrompt 把非空结果原样作为单独一行插入安装章提示词。
  3. 若结果为空，该行精确替换为：“当前页面暂未拿到项目目录，请回到 Axhub Make 管理页打开本项目。”
  4. useMemo 以 projectPath 为依赖重新生成提示词；不读取 URL、文件系统或浏览器存储。

当前可访问性属性

  • 侧栏使用 aside aria-label="新手指导目录"，章节信息 dl 使用 aria-label="章节信息"。
  • 每个正文 section 的 aria-labelledby 指向同区标题；主要图片都有描述性 alt。
  • 沟通成本总图、AI 流程、效果不确定性和时间不确定性分别有 aria-label；仅用于连接的箭头设 aria-hidden="true"。
  • 目录有显式 :focus-visible 描边；复制和页脚按钮依赖浏览器原生焦点表现。外链图标没有单独隐藏，但链接仍有文字“打开”。
  • 当前活动目录通过颜色、左边框和 is-active 表示；源码没有 aria-current。章节标题复用固定 ID，但任何时刻只渲染一个章节，因此运行 DOM 中不重复。

证据与验收

此页把实现边界、可操作验收清单、源码/素材/组件追踪和本规格决策集中在一起。勾选状态只属于本规格页面，不写回原型。

实现边界与风险

  • 原型没有后端请求、认证、权限、发布审批、真实导出动作、Agent 启动动作或模型选择动作；教程只解释并截图示意这些外部能力。
  • “发布到云端”“导出 Axure/Figma/HTML”“获取局域网地址”和未来在线原型都是说明性内容，不代表本组件执行对应业务。
  • 模型名、版本、价格/能力评价和效率数字是当前静态文案，不由服务端校验，也没有日期或可用性提示。
  • 复制使用已弃用但仍常见的 execCommand 作为优先路径；若浏览器限制两个剪贴板路径，UI 会显示“复制失败”2.2 秒。
  • 未知但字符合法的章节 ID 会显示第一章而不规范化 Hash；导航后才会写成有效 #page=。
  • 当前没有学习完成持久化；底部勾形图标不可交互。只有本规格的验收 checkbox 使用 localStorage。
