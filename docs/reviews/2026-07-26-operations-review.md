# 需求文档 Review 问题清单 — 运营角色

**Review 角色**：资深运营专家
**评审对象**：
- `openspec/changes/enhance-prototype-tool/proposal.md`
- `openspec/changes/enhance-prototype-tool/design.md`
- `openspec/changes/enhance-prototype-tool/tasks.md`（参考）

**评审维度**：增长 / 留存 / 数据分析 / 用户上手路径 / 分享传播机制 / 使用数据埋点

## 一、增长问题

### 🔴 高

- **Q1. 缺少用户获取与冷启动策略**
  文档通篇未提"用户从哪里来"。Axhub-Make 本身已有用户基础，但 fork 后的 `axhub-proto-enhanced` 是独立项目，用户迁移路径是什么？是上游用户自然升级、还是全新获客？没有冷启动策略，功能做得再好也无法触达目标用户。

- **Q2. 缺少分享传播机制设计**
  运营视角下，原型工具天然具备传播属性（PM 生成原型 → 发给开发/设计/老板评审）。但文档完全未提：
  - 生成的 HTML 是否带品牌水印/来源标识？（"Made with axhub-proto-enhanced"）
  - 是否支持生成可分享的在线链接（而非仅下载文件）？
  - 是否支持嵌入到 Notion/飞书/语雀等协作平台？
  没有传播钩子，工具只能在现有用户圈内闭环，无法形成裂变。

- **Q3. 缺少模板/示例库的获客价值定位**
  PM Review 已提到模板库（Q19），但从运营角度补充：模板不仅是提效工具，更是**获客入口**。用户搜索"后台管理系统原型模板"时，如果 axhub-proto-enhanced 的模板能被搜索引擎收录，就是持续的免费流量来源。文档未将模板定位为增长资产。

### 🟡 中

- **Q4. 缺少与上游 Axhub-Make 的用户关系策略**
  fork 后两个项目并存，用户会困惑"该用哪个"。需要明确：
  - 是否在 Axhub-Make 的 README/文档中引导用户到增强版？
  - 是否保持品牌一致性（名称、Logo、域名）降低认知成本？
  - 上游作者是否知情/认可？关系处理不好会导致社区分裂，影响口碑传播。

- **Q5. 缺少定价/商业化模式（即使是开源）**
  文档未提项目性质：纯开源免费？未来有 Pro 版？SaaS 托管版？不同的商业化路径直接影响功能优先级（例如：HTML 导出带水印 → 付费去水印；多页面批量导出 → 付费功能）。运营需要提前介入商业模式设计。

## 二、留存问题

### 🔴 高

- **Q6. 缺少用户上手路径（Onboarding）设计**
  文档只描述功能，未描述"新用户第一次打开后 5 分钟内能完成什么"。关键缺失：
  - 是否有新手引导（示例项目、交互式教程）？
  - AI 生成失败后用户怎么办？（重试？手动从零开始？）
  - 手动编辑画布的学习成本如何降低？（Figma 用户迁移成本、快捷键对照表）
  没有 Onboarding 设计，新用户流失率会极高。

- **Q7. "AI 生成 → 手动微调 → 再 AI 优化" 的留存陷阱**
  PM 已指出冲突解决机制缺失（Q16），运营角度补充：这条工作流是**留存关键路径**，如果"再 AI 优化"会覆盖手动修改，用户会产生强烈的不信任感，直接流失。需要设计"AI 修改预览 → 用户确认 → 应用"的确认链路，并在 UI 中显著提示。

- **Q8. 缺少项目数据持久化与迁移策略**
  用户花了 2 小时做的原型，刷新页面后丢失 = 永久流失。文档未提：
  - 自动保存频率？本地存储 vs 云端同步？
  - 项目文件格式是否向后兼容？（v1.0 的项目在 v1.1 能否打开？）
  - 是否支持导入/导出项目文件（.zip / .json）？这是用户资产，直接影响留存。

### 🟡 中

- **Q9. 缺少用户反馈闭环机制**
  运营需要持续收集用户反馈来优化产品，但文档未提：
  - 应用内反馈入口（如"这个功能好用吗？"）
  - 错误自动上报（Sentry / 自建）？
  - 用户行为问卷触发时机（如导出后询问满意度）？
  没有反馈闭环，迭代方向全靠猜。

- **Q10. 缺少社区/内容运营规划**
  原型工具的用户会产出大量设计稿/模板，这是天然的 UGC 内容。是否考虑：
  - 官方模板社区（用户上传/下载模板）？
  - 优秀案例展示（Gallery）？
  - 用户作品分享激励（如导出时推荐分享到 Twitter/小红书）？
  社区能显著提升留存，但完全未提。

## 三、数据分析问题

### 🔴 高

- **Q11. 完全缺失数据埋点与 analytics 规划**
  这是运营评审中最严重的问题。文档没有任何关于数据收集的说明，意味着上线后无法回答：
  - 用户最常用的功能是什么？（AI 生成 vs 手动编辑 vs 导出）
  - 用户在哪个环节流失？（生成失败？编辑太复杂？导出不满意？）
  - 哪种组件使用频率最高？（指导组件库扩展优先级）
  必须补充埋点方案，建议至少覆盖：
  - 页面浏览（PV/UV）
  - 功能点击（AI 生成按钮、导出按钮、各组件使用次数）
  - 转化漏斗（生成 → 编辑 → 导出 → 分享）
  - 错误事件（AI 生成失败率、导出失败率）

- **Q12. 缺少核心指标（North Star Metric）定义**
  运营需要北极星指标来衡量产品健康度。建议候选：
  - 周活跃导出用户数（WAU with Export）
  - 平均每个项目编辑时长（反映工具粘性）
  - 生成到导出的转化率（反映核心链路健康度）
  文档完全未提指标定义。

### 🟡 中

- **Q13. 缺少 A/B 测试与实验文化**
  手动编辑画布是重大功能，但用户是否真的需要？建议通过 A/B 测试验证：
  - 对照组：AI 生成 + 仅代码编辑
  - 实验组：AI 生成 + 手动画布编辑
  观察留存率、导出率差异。文档未提任何实验设计。

- **Q14. 缺少用户分层与精细化运营基础**
  不同用户群体需求差异大：
  - 学生/个人用户（免费、简单、快速）
  - 企业 PM（复杂组件、团队协作、品牌定制）
  - 设计师（高保真、精细调整）
  文档未提用户分层，运营无法制定差异化策略。

## 四、用户上手路径专项问题

### 🔴 高

- **Q15. 首次使用体验（FTUE）完全未设计**
  新用户打开工具后看到什么？空白画布？示例项目？文档未描述 FTUE，这是运营最关注的转化漏斗顶端。建议：
  - 首次打开自动加载示例项目（如"电商后台 Dashboard"）
  - 3 步引导浮层：1. 输入需求 → 2. AI 生成 → 3. 点击导出
  - 提供"从 Axure 导入"作为替代入口（吸引 Axure 存量用户）

- **Q16. 缺少学习资源与帮助中心规划**
  手动编辑画布是复杂功能，需要配套：
  - 视频教程（3 分钟上手）
  - 快捷键速查表
  - 常见问题（FAQ）
  - 组件使用文档
  文档未提任何学习资源建设。

### 🟡 中

- **Q17. 缺少多语言/本地化运营考量**
  Axhub-Make 是中文工具，但增强版是否要面向国际市场？这影响：
  - UI 文案语言
  - 模板内容（中文业务场景 vs 英文业务场景）
  - 社区运营渠道（中文：即刻/小红书/掘金；英文：Twitter/Product Hunt）

## 五、分享传播机制专项问题

### 🔴 高

- **Q18. 导出物缺少传播属性设计**
  用户导出的 HTML/图片是传播载体，但文档未提：
  - 是否添加"Made with axhub-proto-enhanced"页脚/水印？
  - 是否支持生成分享海报（自动截图 + 项目信息）？
  - 是否支持生成在线预览链接（部署到 Vercel/Netlify 一键分享）？
  没有这些，工具无法通过用户作品自然获客。

- **Q19. 缺少社交媒体分享集成**
  建议增加：
  - "复制分享链接"按钮（生成带预览图的 URL）
  - 一键分享到 Twitter/LinkedIn/小红书（带项目截图）
  - 导出时自动生成 Open Graph 标签（分享到社交媒体时显示预览卡片）

### 🟡 中

- **Q20. 缺少 SEO/ASO 策略**
  如果做在线版，SEO 是重要获客渠道：
  - 模板页面是否 SSR/SSG 供搜索引擎抓取？
  - 是否针对"Axure 替代""AI 原型工具"等关键词优化？
  - 是否考虑做 Chrome 插件（"一键将当前页面转为原型"）？

## 评审结论

从运营视角看，本文档**技术导向过重，用户导向严重不足**。最大的盲区是：

1. **零数据思维**：没有埋点、没有指标、没有漏斗，上线后无法优化
2. **零传播设计**：工具再好，没有分享机制就无法增长
3. **零留存策略**：没有 Onboarding、没有反馈闭环、没有社区，用户来了就走

**建议**：
- 在 proposal.md 中补充"运营与增长"章节，明确目标用户、获客策略、核心指标
- 在 design.md 中补充"数据埋点架构"和"分享传播设计"
- 将"数据埋点"加入 tasks.md 的 Phase 1（与项目初始化并行，而非事后补）
- 重新定义成功标准，加入可度量的运营指标（如：周活跃导出用户 ≥ 100、分享率 ≥ 15%）

**运营角色评审结论：打回补充，当前版本不具备上线运营条件。**
