## 二、仍存在的问题（7 项）

### P1. CSS 伪类 / 动态值映射规则缺失（原 T4）
- **缺口**：`:hover / :active / :focus` 样式 → Axure 交互样式（OnMouseOver 等）的映射规则未写入 CSS_TO_AXURE_MAP；`calc()`、百分比、负值、`vw/vh` 单位的处理策略未定义
- **影响**：Axure 侧悬停效果实现路径不明，测试无法验证"按钮悬停态在 Axure 中是否复现"
- **建议**：在 design.md CSS 映射表补一节"伪类与动态值映射规则"，并在 TEST_SPEC.md §1.2 为按钮/输入框/链接添加"悬停态在 Axure 中可复现"的验收路径

### P2. Axure 回归测试的自动化机制未定义（原 T5）
- **缺口**：TEST_SPEC.md §3.2 仅列"Axure 导出回归测试通过"作为一项 checklist，但未说明：
  - 是人工对照《组件-Axure 可编辑性矩阵》逐项点击，还是有 .rp 文件的可编程 diff？
  - 测试用 .rp 基线文件存放路径与版本管理策略
  - CI 环境（GitHub Actions）无法运行真实 Axure，是否仅跑 Bridge mock？
- **建议**：在 TEST_SPEC.md 新增 §3.4 "Axure 回归测试环境"，明确 mock Bridge 协议 + 真实 Axure 的本地验证频率（建议每周人工一次 + 每次 merge 后 mock 自动化）

### P3. 组件数量 / 嵌套层级 / 数据规模硬上限未定义（原 T9）
- **缺口**：TEST_SPEC.md 仅给"100+ 组件渲染 ≤5s"的下限，未给上限；嵌套层级（容器套容器）最大允许深度未定义；表格 1000+ 行的虚拟化策略未定义
- **建议**：在 TEST_SPEC.md §四 新增"容量上限"指标：单页组件数上限（建议 500）、嵌套深度上限（建议 8 层）、表格行数上限（建议 1000，超出启用虚拟滚动）

### P4. 上游同步的回滚策略未定义（原 T10）
- **缺口**：TEST_SPEC.md §3.3 冲突处理流程终止于"创建 issue / 人工介入"，未说明同步失败如何快速回到上一稳定版本（git tag？分支保护？）
- **建议**：在 TEST_SPEC.md §三 增加"回滚标准"小节：每次成功 sync 后打 `upstream-sync-YYYYMMDD` tag，失败时 `git reset --hard <tag>` 一键回滚

### P5. 禁止修改的上游核心文件清单未提供（原 T11）
- **缺口**：仅规定 ESLint 禁止改 upstream/，但未列出"上游关键接口文件清单"（如 `axhub-export-core/index.ts` 的公共导出签名），上游 API 变更无法被静态检测
- **建议**：在 design.md 补一份 `UPSTREAM_API_LOCK.md`，列出本地 patches/ 与 src/integration/ 依赖的上游符号清单，CI 中加入"符号漂移检测"

### P6. AI 异常输入三场景未完整覆盖（原 T13）
- **缺口**：TEST_SPEC.md §六 未列出"非法 JSON / 未知组件类型 / 循环嵌套"三种第 1 轮明确点名的输入异常的验收标准
- **建议**：在 §六 异常处理表新增三行：非法 JSON → 拒绝生成 + 错误提示；未知组件类型 → 占位矩形 + 警告日志（已在 §1.4 有，但需复制到 §六 保持单一来源）；循环嵌套 → 截断 + 警告

### P7. E2E 测试环境的 Axure 取舍未明确（原 T15）
- **缺口**：CI 环境（Linux container）无法运行真实 Axure，本地 macOS/Windows 才能跑 Bridge，这种割裂未在 TEST_SPEC.md 中说明
- **建议**：明确"双层测试策略"——CI 跑 mock Bridge 协议层测试，本地/定时任务跑真实 Axure 集成测试；并在 §3.2 必过测试清单中标注每项的执行环境（CI / 本地）

## 三、新增问题（修订版引入，3 项）

### N1. L2 级"部分可编辑"的判定主观
- **位置**：TEST_SPEC.md §1.1 L2 定义"样式需通过格式刷"
- **问题**："格式刷"是 Axure 中的操作动作，不是可编辑性属性；测试时无法据此判定"通过 / 不通过"。建议改为：L2 = 文本、尺寸、位置可直接编辑；样式需通过 Axure 属性面板修改（不允许需要"重建 widget"）

### N2. 三模式"布局一致性 ≤1px"在跨浏览器下不可达
- **位置**：TEST_SPEC.md §2.1
- **问题**：≤1px 偏差在 Chrome/Firefox/Safari 间由于字体渲染差异基本不可达；建议放宽为"同浏览器下 ≤1px，跨浏览器 ≤3px 且布局结构一致"

### N3. 数据埋点验收与 ANALYTICS_SPEC 存在重复
- **位置**：TEST_SPEC.md §七 vs ANALYTICS_SPEC.md §二/§三
- **问题**：两份文档均定义了必埋事件清单与核心指标，存在双源同步风险；建议 TEST_SPEC.md §七 仅引用 ANALYTICS_SPEC，不重复定义
