## 高严重问题汇总（🔴 38 项）

### 一、核心架构决策悬空（FE + BE）

| # | 问题 | 提出者 | 说明 |
|---|------|--------|------|
| H1 | **画布底座选型未决策**：React DnD vs 自研 vs 复用 Excalidraw | FE | 代码库已深度集成 Excalidraw，新建独立 DnD 画布 = 两套画布模型并存 |
| H2 | **导出路径自相矛盾**：组件树 vs DOM 两条路径 | FE | `htmlToAxure` 是 DOM selector 遍历，不读组件树；`ComponentDefinition.axureMapping` 是死字段 |
| H3 | **export-core 是预编译 vendor 包，无法"增强"** | FE | 只有 dist/ 无源码，"扩展"等于 fork 源码重建，与 weekly merge 策略冲突 |
| H4 | **Bridge 协议契约完全缺失** | BE | 只有 `/available` 和 `/copyaxvg`，增强导出需要扩展消息格式，版本协商机制未定义 |
| H5 | **fork `axhub-export-core` 与上游同步机制自相矛盾** | BE | vendor 深度改造后，上游同步就是三方合并，冲突概率极高 |
| H6 | **组件树持久化与"AI 再生成覆盖手动修改"无 merge 策略** | BE/QA | 核心工作流"AI生成→手动微调→再AI优化"中，第二次 AI 生成若不 diff，用户手动修改全部丢失 |

### 二、手动编辑画布边界不清（PM + 设计 + QA）

| # | 问题 | 提出者 | 说明 |
|---|------|--------|------|
| H7 | **缺少撤销/重做（Undo/Redo）机制** | 设计/QA/BE | 手动编辑画布没有 undo 栈设计，是编辑器的基本盘 |
| H8 | **画布交互规范完全缺失** | 设计 | 选中态、悬停态、拖拽反馈、对齐参考线、键盘快捷键、多选框选等 8 类交互未定义 |
| H9 | **AI 生成与手动编辑的并发/覆盖语义未定义** | FE/PM/运营 | 用户在编辑时 AI 重新生成，组件树如何 merge？无锁、无 diff、无冲突策略 |
| H10 | **缺少设计 Token / 视觉规范定义** | 设计 | 20+ 组件没有颜色、字号、间距、圆角、阴影等设计 token |
| H11 | **组件状态规范缺失** | 设计 | 所有组件仅描述"默认态"，未定义 hover/active/focus/disabled/loading/error 等状态 |
| H12 | **缺少数据持久化与项目模型定义** | PM/运营 | 项目如何保存？单文件 JSON？多文件目录？自动保存频率？ |

### 三、Axure 导出与预览（QA + BE + FE）

| # | 问题 | 提出者 | 说明 |
|---|------|--------|------|
| H13 | **缺少 Axure 可编辑性的量化验收标准** | QA | "可编辑"无定义：能修改文本？调整尺寸？改样式？绑定交互？覆盖哪些 Axure 版本？ |
| H14 | **高级组件（图表/地图/富文本）降级策略缺失** | QA/设计/BE/PM | Axure 无原生 widget，导出后是矩形+文本拼合？还是 Inline Frame？ |
| H15 | **CSS→Axure 布局映射核心难题未覆盖** | FE | Flexbox/Grid、position:fixed/sticky、overflow 滚动、z-index、transform 均无映射方案 |
| H16 | **Axure 交互导出基本不可行** | FE | React onClick 是任意 JS，Axure 是 case-based 模型，不存在通用映射 |
| H17 | **三种预览模式的一致性未定义** | QA | iframe/HTML/图片三模式渲染是否像素级一致？交互效果是否保持？ |
| H18 | **HTML 导出的离线兼容性未定义** | QA/BE | 外部资源（CDN 字体、图片）离线降级策略、base64 内联阈值、浏览器兼容性矩阵 |
| H19 | **"standalone HTML"体积与构建成本没有预算** | BE | 内联所有 JS/CSS/字体后单文件可能 5MB+，内联策略、字体子集化未定义 |
| H20 | **图片导出、iframe 预览标注"新增"但实际已存在** | FE | `captureDocumentScreenshot` 和 preview bridge 均已实现，存在重复建设风险 |

### 四、上游同步与工程风险（BE + QA + PM）

| # | 问题 | 提出者 | 说明 |
|---|------|--------|------|

| H22 | **目录隔离方案与仓库现状冲突** | BE/FE | `upstream/` + `src/` 与现有 `client/` + `src/server/` + `vendor/` 紧密结构不兼容 |
| H23 | **"每周检查上游更新"无自动化细节** | BE/QA | sync 脚本冲突时是中断还是自动 ours/theirs？CI 是否跑全量测试？ |
| H24 | **关键路径错位：手动画布应最后做，但 Phase 2 就启动** | PM | 最大风险模块排最前，一旦做不出来，后续全部 blocked |
