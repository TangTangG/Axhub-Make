## 二、高优问题汇总（需修复）

### 2.1 设计 Token 双源冲突（UI/FE/BE 共同发现）

| 角色 | 问题描述 | 证据 |
|------|---------|------|
| UI设计师 | PLAN.md 使用 Ant Design 色值（#1890ff），DESIGN_SPEC.md 使用 Apple HIG 色值（#0066cc） | 色值/命名/维度全面不一致 |
| 前端开发 | Token JSON schema 不一致，PLAN.md 与 design.md 字段命名不同 | `color.primary` vs `color.primary.value` |
| 后端开发 | 设计 Token 双源冲突，需在动工前修复 | 同一问题 |

**修复方案**：
- 删除 PLAN.md 任务 2.1 中的 JSON
- 改为"引用 DESIGN_SPEC.md §1，按 SPEC 生成 tokens.json"
- 增加 `scripts/generate-tokens.ts` 自动生成

### 2.2 组件接口不一致（UI/FE 共同发现）

| 角色 | 问题描述 |
|------|---------|
| UI设计师 | `ComponentDefinition` 缺少 `icon`/`defaultProps`/`version`/`axureMapping` 字段 |
| 前端开发 | PLAN.md 接口与 design.md 接口字段不匹配 |

**修复方案**：
- 以 design.md §2 的 `ComponentDefinition` 为唯一接口蓝本
- 补充 L1-L4 分级定义到 DESIGN_SPEC.md

### 2.3 遗留问题登记与实际任务脱节（QA 发现）

| 登记项 | PLAN 声称 | 实际状态 | 修复方案 |
|--------|----------|---------|---------|
| #2 容量上限 | ✅ 已修复 | 无任务负责落地 | 增加任务 4.3「容量上限守卫」|
| #3 AI 异常输入 | ✅ 已修复 | 无任务负责实现 | 增加任务 3.4「AI 输出校验器」|
| #4 回滚策略 | ✅ 已修复 | Phase 1 无对应任务 | 增加任务 1.6「同步 tag 与回滚机制」|
| #5 上游 API 变更检测 | ✅ 已修复 | Phase 1 无对应任务 | 增加任务 1.7「UPSTREAM_API_LOCK.md」|

### 2.4 Axure 导入测试断言方式不可执行（QA 发现）

**问题**：`importAxureFile` 函数不存在，Axure `.rp` 无可编程接口

**修复方案**：
- 拆分为自动化层（快照测试）+ 人工验收层（checklist）
- 验收标准：自动化 100% + 人工 15/15 通过

### 2.5 E2E 测试未声明环境分层（QA 发现）

**问题**：CI 无法运行真实 Axure RP

**修复方案**：
- CI 层：使用 `msw`/`nock` mock Bridge 端点
- 本地层：`npm run test:e2e:real-bridge` 连接真实 Bridge
- `package.json` scripts 显式区分

### 2.6 里程碑工作量过于乐观（PM 发现）

**问题**：M3-M5 单周完成 4 类组件导出过于乐观

**修复方案**：
- M4 和 M5 合并为 Week 4-5 双周里程碑
- 或明确优先级，允许布局组件延后

### 2.7 缺少上游导出机制 Spike（PM 发现）

**问题**：未验证 `axhub-export-core` 的输入/输出/扩展点

**修复方案**：
- Phase 3 开始前增加 1-2 天 Spike
- 输出《上游导出机制分析报告》

### 2.8 埋点验收标准不一致（运营发现）

**问题**：PLAN 仅要求"必埋事件 100% 触发"，未明确 19 个事件清单

**修复方案**：
- 引用 ANALYTICS_SPEC.md §2 作为验收依据

### 2.9 缺少指标计算验证（运营发现）

**问题**：无"数据 → 指标 → 看板"端到端验证

**修复方案**：
- Phase 6 增加"指标计算验证"任务

### 2.10 基础组件状态集与 COMPONENT_MATRIX 不一致（UI 发现）

**问题**：PLAN 验收标准未列出每组件的完整状态集

**修复方案**：
- 验收标准改为直接引用 COMPONENT_MATRIX 的状态集
