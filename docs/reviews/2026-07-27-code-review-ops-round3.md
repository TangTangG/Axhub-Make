## 四、是否可进入 Phase 4

**否（No-Go）。**

理由：
1. **H1 是数据体系的根基**：`app_open` 与 `export_axure_start/success/fail` 是激活漏斗与北极星指标（导出成功率）分子分母的唯一数据来源。三轮 Review 过去，全仓库 `tracker.track` 调用仍停留在 3 处，数据面板上线即白板——这是第 1 轮就定性的阻断项，两轮修复窗口均未解决。
2. **H4 是合规硬要求**：spec §五承诺"退出数据分析"开关，当前无任何运行时 API。且第 2 轮的 staged 实现已丢失（R3-H1），等于从零重做。
3. **H2 接线缺失使脱敏工具形同虚设**：合规风险面（prompt 原文上报）依然存在。

**进入 Phase 4 的最低条件（与第 2 轮一致，未变）：**
1. 应用入口接入 `app_open`；Axure 导出路径接入 `export_axure_start/success/fail`（三处）；
2. `tracker.track()` 内接入 `sanitizePrompt`（对 `prompt_text` 自动脱敏），并修订 `types.ts` L26 的必填声明；
3. 重新实现并**提交** `setEnabled/optOut`（含清空队列 + 清除本地缓存/匿名 ID）；
4. 顺手清理 R2-M1~M4 四个遗留中优（工作量合计 < 1h）。

预计工作量：2–3h。完成后再做一次快速验证（第 3.5 轮）即可放行。

## 五、运营备注
