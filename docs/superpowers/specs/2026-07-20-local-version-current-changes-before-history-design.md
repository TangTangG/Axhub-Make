# 本地版本待提交信息前置设计

## 背景

“版本和协作”的“本地”面板当前依次展示项目信息、历史版本、更改文件和提交版本。历史版本列表较长时，用户需要滚动越过全部历史记录，才能查看当前更改并提交新版本。

## 目标

让当前待处理内容优先于历史记录展示。存在未提交更改时，本地面板按以下顺序排列：

1. 信息
2. 更改文件
3. 提交版本
4. 历史版本

## 范围

- 只调整 `VersionCollaborationPanel` 中非历史版本状态下的卡片顺序。
- 保持“更改文件”和“提交版本”原有的显示条件、内容、按钮行为和样式不变。
- 保持“历史版本”的显示条件、列表内容和当前版本标记不变。
- 历史版本快照的只读展示不变。
- 按原有产品行为，没有未提交更改时不展示“更改文件”和“提交版本”，历史版本紧随“信息”展示。

## 实现方式

把非历史版本的“历史版本”渲染块移到“更改文件”和“提交版本”渲染块之后，不引入新的状态、组件或样式。为源码结构测试增加顺序断言，锁定“更改文件 → 提交版本 → 历史版本”的排列，避免以后回退。

## 验证

- 运行 `VersionCollaborationPanel.source.test.ts`。
- 确认有未提交更改时三个区块的源码顺序为“更改文件 → 提交版本 → 历史版本”。
- 确认现有的显示条件和历史版本只读逻辑测试继续通过。
