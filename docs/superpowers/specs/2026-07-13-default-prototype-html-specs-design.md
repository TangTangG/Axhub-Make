# 默认三原型 HTML 主规格设计

## 目标

为 Make Client 模板内三个默认原型补齐 HTML 主规格：

- `annotation-demo`
- `beginner-guide`
- `touch-and-talk-annotation-demo`

规格是对当前实现的反向归纳，只记录源码、原型内资料、现有资源和仓库规则能够证明的事实。不得将改进建议、推测需求或未来能力写成既定方案。

## 交付位置

每个原型只维护一个 HTML 主规格：

- `client/src/prototypes/annotation-demo/.spec/spec.html`
- `client/src/prototypes/beginner-guide/.spec/spec.html`
- `client/src/prototypes/touch-and-talk-annotation-demo/.spec/spec.html`

不修改原型实现、样式、素材、目录资料或运行时配置。

## 内容架构

三份规格采用相同的核心骨架，并允许按原型特点增加专属章节：

1. 文档定位与事实来源
2. 当前方案、目标用户与核心任务
3. 范围与非目标
4. 信息架构、页面或章节清单、Hash 路由
5. 逐页面或逐章节内容规格
6. 用户流程、交互与反馈状态
7. 内容、数据、截图和外部链接来源
8. 视觉结构、响应式和可访问性事实
9. 运行时依赖与宿主集成
10. 已知边界与当前未实现状态
11. 可验证的验收标准
12. 规格条目到实现文件或组件的追溯关系
13. 重要决策记录

“设计基底”章节只描述当前实现能够观察到的设计语言及其证据；没有明确 `DESIGN.md` 时直接说明，不反向杜撰主题来源。

## HTML 表达能力

在仓库 HTML 规格模板基础上增强文档阅读与评审能力：

- 多页面侧栏导航，并用 URL Hash 保存当前文档页，支持刷新和深链。
- 全文检索与结果计数，用于快速定位规格、组件、状态和源码路径。
- 事实来源、已知边界和追溯证据使用可折叠区域，正文仍保持完整可读。
- 用户流程使用 Mermaid 源码容器表达；外部脚本不可用时保留可读文本降级，不预建宿主派生文件。
- 验收项使用可交互复选框，状态仅保存在当前浏览器，不与 Make 宿主或原型状态同步。
- 使用语义化标题、表格说明、键盘焦点、ARIA 状态、横向表格容器、窄屏布局和打印样式。
- 脚本只负责文档自身交互，不读取或改写原型状态。

## 原型专属重点

### 标注演示

重点描述角色、六章目录文档、页面中的工作流演示、状态切换、指标变化、资料内联及宿主路由信息。现有 `annotation-source.json` 和 `docs/*.md` 是事实来源之一。

### 新手指导

重点描述安装 Agent、选择模型、下达指令、创建、编辑、发布和进阶指导等章节，包含提示词复制成功/失败反馈、项目路径注入、外部链接、截图用途、前后章导航和当前内容口径。

### 批注演示

重点描述 Touch And Talk 教学章节、点选与语音批注流程、快速执行提示词/技能、截图说明、常用技巧、扩展场景和章节导航。

## 校验策略

- 将每一条功能、状态、文案或约束追溯到当前源码、原型资料或仓库指南。
- 扫描 `TODO`、`TBD`、模板占位符、空表格和无法证明的断言。
- 校验 HTML 结构、内部 ID、导航目标、Hash 深链、搜索、复选框持久化和 Mermaid 降级。
- 运行三个原型的 ready 检查，确认补充 `.spec/spec.html` 没有影响原型预览。
- 检查 `git diff --check`，并仅审阅三份主规格及本设计文档的差异。

## 完成标准

- 三个固定路径均存在且只有 HTML 主规格作为生效规格。
- 文档没有占位符、未决问题或改进建议。
- 当前实现中的主要章节、流程、交互、状态、内容来源、视觉和运行时边界均有对应规格。
- 三份文档交互一致、独立可读，并能在 Make 中用于阅读和评审。
- 原型预览验收仍为 `READY`。
