# Axhub Make Axure 导出失败 FAQ 设计

## 背景

Axhub Make 的 Axure 导出包含可编辑原型、动态原型和 Runtime 相关路径。失败原因既可能来自本地 Axure Bridge、版本和多开实例，也可能来自 Windows 字体兼容或动态原型自身的复制方式。FAQ 的阅读对象是 AI，因此可以直接提供 host、端口、接口和版本信息，但正文仍应保持短小，按用户的错误表现选择分支。

## 目标

在 `docs/faq.md` 增加一个“发布或者导出到 Axure 失败怎么办？”条目，优先要求 AI 检查当前“使用说明”和字体准备，再按三类表现给出恢复路径。

## 已确认的技术事实

- Axhub Make 默认通过 `http://localhost:32767` 访问 Axure Bridge。
- Bridge 可用性检查路径是 `/available`，复制数据路径是 `/copyaxvg`。
- 当前界面使用说明要求打开 3743 及以上版本的 Axure。
- Axure 必须处于运行状态；多开 Axure 时实际端口可能不一致，关闭最初打开的实例也可能使原端口失效。遇到此类情况，优先关闭全部 Axure 实例后重新启动，恢复初始可用端口。

## FAQ 结构

### 统一前置检查

先确认用户是否按“使用说明”完成 Axure 准备工作，尤其是字体配置。未完成时先补齐准备工作，不要直接把错误归因到导出功能。

### 可编辑原型 / 复制原型失败

说明 Make 默认请求 `localhost:32767`，并检查 Axure 是否已打开且版本至少为 3743。多开或关闭首个 Axure 实例后端口可能变化；建议全部关闭并只重新打开一个符合版本要求的 Axure，再重试。可提及 `/available` 和 `/copyaxvg`，帮助 AI 判断是 Bridge 不可用还是复制请求失败。

### Windows 粘贴或编辑时报错

说明常见原因是字体兼容。优先引导用户使用 [Axhub Chrome 扩展](https://axhub.im/chrome/) 代替普通复制，因为扩展可以识别系统字体；也可以建议将 Axure 更新到最新版本。该分支仍以正确完成字体使用说明为前提。

### 动态原型复制后失败

- **无法复制：** 不要继续反复尝试复制，改用 [Runtime 元件库](https://axhub-work.feishu.cn/file/ZR2UboHQ9oBsQsx48lscSMpenue) 的下载封面方法：下载 Runtime 封面，回到 Axure，双击对应 Runtime 元件，用下载的封面替换原图片。
- **可以复制但不显示：** 优先判断 Axure 客户端兼容性，建议升级 Axure；也可以下载 SVG 替换对应内容。前提是字体已经按使用说明正确配置。

动态原型复制不是所有用户都能稳定成功，Windows 用户受字体兼容影响尤其明显；下载封面是“无法复制”时的替代路径，不是另一条复制命令。

## 范围

- 只修改 `docs/faq.md`。
- 不修改 Bridge 实现、导出弹窗、启动指导或 AI 用户指导。
- 不写操作系统级进程命令，不虚构未确认的 Axure 版本、端口或客户端名称。
- FAQ 保持短小，只保留 AI 需要作判断和恢复操作所需的技术信息。

## 验证

- FAQ 包含默认 host、端口、两个 Bridge 路径和 3743 版本要求。
- FAQ 明确 Axure 必须打开，多开或首个实例关闭后应全部关闭重启。
- FAQ 包含 Chrome 扩展和 Runtime 元件库两个链接。
- “无法复制”分支明确改用下载封面替换图片；“复制但不显示”分支明确升级或 SVG 替换。
- FAQ 提醒先按使用说明配置字体。
- `git diff --check` 无空白错误，最终实现只修改 `docs/faq.md`。
