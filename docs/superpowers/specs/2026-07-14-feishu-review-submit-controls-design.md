# 飞书评审提交控件精简设计

## 目标

精简人工评审底部的提交方式配置，让两行标题与两组右侧操作形成稳定、对称的布局，同时保持现有底部区域高度不变。

## 文案与结构

- 将“飞书评审”统一改为“飞书提交”，与“局域网提交”保持同一命名方式。
- 第一行继续显示“提交报告”及已有报告操作，不改变上传、技能提交和获取飞书的业务逻辑。
- 第二行增加 `ListChecks` 图标和“提交方式”标题，图标尺寸、标题字号、字重、颜色及间距与第一行的 `UploadCloud` 和“提交报告”一致。
- 第二行右侧连续排列两个可勾选配置项：
  - `局域网提交`
  - `飞书提交`
- 两个配置项作为一个整体靠右排列，与第一行右侧的报告操作组对齐。

## 控件行为

- 使用项目现有 `Checkbox` 组件替换两个 `Switch`。
- 复选框仅表达是否启用，继续调用现有局域网和飞书启用回调，不改变服务端配置结构。
- 两个配置项保留独立 pending 状态；提交中的项目暂时禁用自身复选框，不影响另一项。
- 局域网不可用时继续禁用局域网复选框。
- 飞书已绑定时，在“飞书提交”旁保留紧凑的外链图标；不显示原始链接。
- 两个说明图标继续保留在各自配置项旁。

## 布局约束

- 人工评审内容区域继续使用 `h-[72px]`。
- 保持两行，每行继续使用 `h-8`；不得增加第三行。
- 两行都采用相同的 `justify-between` 结构：左侧为图标标题组，右侧为紧凑操作组。
- 第二行的两个配置项必须位于同一个右侧 flex 组内，不得分别分散到两端。
- 布局继续适配当前 `380px` 侧栏，不使用固定列宽或绝对定位。

## 测试与验收

- 源码测试断言使用 `Checkbox`，且人工评审区域不再使用 `Switch`。
- 断言出现“提交方式”和“飞书提交”，不再出现“飞书评审”。
- 断言“提交报告”和“提交方式”使用相同的标题容器样式，且“提交方式”使用 `ListChecks` 图标。
- 断言第二行使用左右对称结构，两个复选配置项处于同一个右侧组，并继续保持 `h-[72px]`、两行 `h-8`。
- 断言飞书外链仍为图标按钮，原始 URL 不渲染。
- 运行相关 UI 测试、管理端生产构建和 `git diff --check`。
