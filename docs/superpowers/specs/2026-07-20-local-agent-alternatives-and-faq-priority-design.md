# Axhub Make 本地 Agent 替代场景与 FAQ 优先级设计

## 背景

Axhub Make 网页 Agent 覆盖批注直接执行、侧边栏对话和新建场景等操作。用户已有的本地 Agent 即使不能通过网页 ACP 调用，也可以用本地工作流完成这些场景。现有 FAQ 只说明本地 Agent 可以完成绝大多数功能，没有给出网页场景与本地操作的对应关系。

AI 使用指导文档已经把 FAQ 列为参考信息源，但位置在默认客户端教程之后。用户要求提高 FAQ 对相关问题的检索优先级，同时仍只用一句话说明其用途。

## 目标

- 在 `docs/faq.md` 中增加一个简短的场景映射小节，说明三类网页 Agent 操作如何由本地 Agent 替代。
- 在 `docs/guide-users-with-axhub-make.md` 中把 FAQ 移到“参考信息源”首位，并明确遇到相关问题时优先查阅。

## 已确认事实

- 原型改稿批注由本地 `$prototype-comments` 技能处理；`$prototype-annotation` 负责原型说明层，不是本场景的替代技能。
- 侧边栏对话可以由本地 Agent 中的普通对话替代，前提是本地 Agent 打开当前 Make 客户端目录。
- 新建场景提示词输入框在没有选中文字时，支持 Windows `Ctrl+C` 和 macOS `⌘C`。
- 该快捷键会复制由当前提示词、场景类型和场景设置组合成的完整提示词，可粘贴到本地 Agent 中执行。
- 快捷键提示位于发送按钮的悬停提示中，入口较隐蔽，因此 FAQ 需要明确告知。

## FAQ 设计

在“如何设置和使用本地 AI Agent？”下增加“网页 Agent 的常用场景怎样用本地 Agent 代替”小节，使用三条短列表：

- 批注直接执行：在当前 Make 客户端目录中，让本地 Agent 使用 `$prototype-comments` 处理批注。
- 侧边栏对话：直接使用本地 Agent 的对话，并确保它打开当前 Make 客户端目录。
- 新建场景：提示词输入框没有选中文字时，按 Windows `Ctrl+C` 或 macOS `⌘C`，复制包含当前场景设置的完整提示词，再粘贴到本地 Agent 执行；同时指出提示入口位于发送按钮的悬停提示中。

该内容作为一个小节集中呈现，不追加到“常用 Agent 不在列表中”的长段落，也不拆成三个独立 FAQ。

## 指导文档设计

在“参考信息源”中把 FAQ 小节移到第一项，文案保持一句：

> 遇到相关问题时，优先查阅 [Axhub Make FAQ](./faq.md)。

不增加 FAQ 的来源、维护、生成方式或其他说明。用户当前页面、本地项目、GitHub 仓库和默认客户端教程的原有说明保持不变。

## 范围

- 实现阶段只修改 `docs/faq.md` 和 `docs/guide-users-with-axhub-make.md`。
- 不修改本地 Agent、ACP、批注、快捷键或提示词生成实现。
- 不把 `$prototype-annotation` 写成原型改稿批注的执行技能。
- 不把复制提示词写成可见按钮；明确它是提示词输入框中的键盘快捷操作。
- 不增加 FAQ 的维护或生成说明。

## 验证

- FAQ 包含 `$prototype-comments`、本地对话、当前 Make 客户端目录、Windows `Ctrl+C`、macOS `⌘C`、当前场景设置和悬停提示。
- 指导文档中的 FAQ 位于其他参考信息源之前，并且只有一句用途说明。
- 两份文档没有固定扩展本地 ACP 支持范围。
- `git diff --check` 无空白错误，最终实现提交只包含两份目标文档。
