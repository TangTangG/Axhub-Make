# 客户端局域网预览免验证设计

## 目标

允许用户按项目关闭官方客户端预览页的局域网访问验证，方便可信局域网内直接打开原型预览，同时继续保护 Make 管理端和 API。

## 配置与界面

- 在项目设置的局域网区域增加“预览免验证”开关。
- 辅助说明为：“开启后，局域网可直接访问当前项目预览；管理端和 API 仍需验证。”
- 配置保存到当前项目的 `.axhub/make/axhub.config.json`，字段为 `server.skipLanPreviewAuth`。
- `skipLanPreviewAuth` 仅在值严格为 `true` 时生效；缺失、`false`、其他类型或无法读取配置时均按 `false` 处理。
- 默认关闭。现有项目无需迁移，行为保持不变。

## 作用范围

- 开启后，仅当前项目由官方客户端 Vite 预览服务提供的原型预览免除局域网验证。
- Make 管理端、管理端 API、其他客户端项目以及其他发布或预览入口不受影响。
- 已设置的局域网密码、登录会话和短期分享链接继续按现有逻辑工作；开关不修改或清除这些数据。

## 数据流

1. 设置页通过现有 `GET /api/config` 读取 `server.skipLanPreviewAuth`，缺失时展示为关闭。
2. 用户切换并保存后，设置页通过现有 `POST /api/config` 将布尔值写入当前项目配置。
3. 客户端预览插件收到非本机预览请求时，动态读取项目配置。
4. 配置为 `true` 时直接继续预览请求；否则进入现有的密码会话、短期链接和拒绝提示流程。

客户端预览插件按请求读取配置，使设置保存后无需重启客户端预览服务。配置文件很小，该读取只发生在相关预览请求路径，成本可接受。

## 异常与安全边界

- 设置保存失败时，界面提示错误，并恢复为服务端已保存的值，避免界面状态与项目配置不一致。
- 配置文件缺失、损坏、不可读或字段类型错误时默认继续验证，即安全失败。
- 开关不改变管理端的 `lanAccessControl` gate，也不把管理端 API 加入免验证路径。
- 免验证是显式的项目级选择，不提供全局默认开启或旧字段兼容逻辑。

## 验证

- 配置 API 测试：缺失字段返回关闭状态，`true`/`false` 可往返保存，且不影响同一 `server` 对象中的其他字段。
- 设置页测试：展示“预览免验证”短标签和辅助说明，正确加载、保存以及处理保存失败。
- 客户端预览插件测试：默认和关闭状态继续验证；开启时非本机预览直接通过；配置损坏时继续验证；保存后无需重启即可改变行为。
- 安全回归测试：开启项目级免验证后，Make 管理端和受保护 API 的非本机请求仍要求验证。
- 运行相关聚焦测试、所属 workspace 构建和 `git diff --check`。

## 不在范围内

- 不跳过 Make 管理端或 API 的局域网验证。
- 不增加全局免验证开关、IP 白名单、按原型配置或过期时间。
- 不改变密码、二维码、短期链接或登录会话的生命周期。
