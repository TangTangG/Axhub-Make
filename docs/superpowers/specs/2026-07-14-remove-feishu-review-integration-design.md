# 撤下飞书评审集成设计

## 目标

暂时从 Axhub Make 撤下飞书评审提交能力，保留局域网提交、Markdown 报告上传、本地评审报告列表与阅读流程。底部评审区域继续使用当前固定高度和两行布局，不因撤下飞书入口而改变整体样式。

## 产品界面

- 第一行继续显示“提交报告”及现有的报告操作，但不再显示“获取飞书”。
- 第二行继续显示“提交方式”，右侧仅保留“局域网提交”复选框。
- 移除“飞书提交”复选框、说明提示和飞书外链入口。
- 保持底部区域当前的固定高度、间距、标题样式和左右对齐关系。

## 客户端范围

- 移除飞书评审配置、同步结果等客户端类型。
- 移除飞书配置读取、启停和同步 API 方法。
- 移除页面层的飞书状态、加载、启停、同步和打开链接回调。
- 移除组件之间传递的飞书属性和事件。
- 局域网提交和本地报告相关契约保持不变。

## 服务端范围

- 移除 `lark-cli` 能力检查、用户认证、Base 创建、校验和记录同步服务。
- 移除飞书配置读取、启停和同步路由。
- 移除服务端依赖注入中的飞书命令执行器。
- 从评审配置模块移除飞书绑定的类型和读写接口，保留局域网配置的合并写入行为。
- 从报告元数据解析中移除飞书专属来源字段，不影响通用 Markdown 报告字段。

## 数据保留

- 不删除本次调试期间已经创建的飞书 Base。
- 不扫描或改写现有项目中的本地评审配置文件。
- 历史配置中可能存在的 `feishuReview` 字段由新代码忽略，不再读取或更新。
- 不删除已经同步到本地的 Markdown 报告；它们继续作为普通本地报告显示。

## 文档与测试

- 删除飞书集成及飞书控件的旧设计和实施计划，避免继续把已撤下能力描述为现行功能。
- 删除飞书专属服务测试、API 测试和组件断言。
- 更新保留下来的测试，明确验证底部仍为固定高度、只显示局域网提交，并且不再包含飞书入口。
- 运行评审相关 Vitest、服务端构建、前端构建或所属 workspace 规定的等价校验，并执行差异检查。

## 非目标

- 不改变局域网评审提交协议和权限逻辑。
- 不改变报告上传、列表、详情和删除行为。
- 不迁移或删除飞书中的任何数据。
- 不为未来恢复保留隐藏开关、禁用路由或半启用状态；需要恢复时重新设计集成边界。
