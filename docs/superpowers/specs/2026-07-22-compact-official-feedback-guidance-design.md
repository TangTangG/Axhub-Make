# 紧凑的官方问题反馈指导设计

## 背景

当前 AI 指导使用“疑似系统 Bug 时”作为标题，并用独立字段列表展开报告要求。这会让 AI 先判断问题是否属于系统 Bug，也让问题反馈在整份使用指导中占据过大篇幅。

实际规则更简单：遇到问题时可以建议用户向 Axhub Make 官方反馈；用户同意或已经要求反馈时，AI 直接整理 Markdown 报告。报告仍要尽量包含完整的环境和技术信息，但不需要在指导文档中展开成长列表。

## 目标

- 不要求 AI 先判断问题是否属于“疑似系统 Bug”。
- 用户主动要求反馈时直接生成报告，不重复询问是否反馈。
- 保留详尽的环境、版本、复现、错误和日志要求。
- 显著降低该内容在整份指导文档中的篇幅占比。

## 设计

把“疑似系统 Bug 时”章节替换为“向官方反馈问题”，正文只保留两段：

第一段说明触发方式：

> 遇到问题时，可以建议用户向 Axhub Make 官方反馈。用户同意或主动要求反馈时，直接整理一份 Markdown 报告，不再重复询问。

第二段集中说明报告要求：

> 报告格式自由，但应尽量收集可取得的本地环境和技术细节，包括问题摘要、Axhub Make 与 Make 客户端版本、操作系统和运行环境版本、相关浏览器或第三方软件版本、问题入口、复现步骤、实际与预期结果、出现频率、完整报错、控制台/服务端/客户端日志、相关网络请求和响应、截图或视频、升级前后结果、影响范围和临时绕过方式。无法确认的内容标记为“未确认”，不要猜测；报告和附件保存在已忽略的 `.local/` 目录，提供给官方前完成脱敏。

前面的版本升级优先规则保持不变，但不再作为生成反馈报告的前置门槛在本节重复说明。

## 范围

- 实现阶段只修改 `docs/guide-users-with-axhub-make.md`。
- 不修改工作原则和标准指导流程中的升级优先规则。
- 不修改 FAQ、README、产品代码或用户现有改动。
- 不规定官方提交渠道或固定报告模板。

## 验证

- 标题为“向官方反馈问题”，文档不再包含“疑似系统 Bug 时”。
- 用户同意或主动要求反馈时直接生成报告，不再重复询问。
- 报告要求仍覆盖核心版本、环境、复现、错误、日志、网络证据、升级结果和脱敏。
- 反馈章节只有两段正文，不使用字段列表。
- `git diff --check` 无空白错误，最终实现提交只包含目标指导文档。
